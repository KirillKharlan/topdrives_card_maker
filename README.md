# Card Maker (Top Drives fan cards)

Офлайн-приложение на Flutter для создания фанатских карточек. Все шаблоны,
рамки классов, теги и баннер приза уже внутри приложения (assets/).

> Код написан без запуска Flutter (в среде, где я его писал, Flutter не было),
> поэтому первый запуск, скорее всего, потребует мелких правок. Координаты текста
> в `assets/templates/standard.json` подобраны по твоим скриншотам и рамке B и
> нуждаются в подгонке на глаз.

## Первый запуск

```bash
cd topdrives_card_maker
flutter create --platforms=android,ios --project-name topdrives_card_maker .
# проверь, что lib/main.dart остался нашим (если нет, верни из архива)
flutter pub get
flutter run
```

### Шрифт
Roboto Condensed (лицензия SIL OFL) уже лежит в `assets/fonts/` и подключён в `pubspec.yaml`,
ничего докачивать не нужно.

### Разрешения
- **iOS** (`ios/Runner/Info.plist`): `NSPhotoLibraryUsageDescription`
  и `NSPhotoLibraryAddUsageDescription`.
- **Android**: `minSdkVersion 21` (нужно для пакета `gal`); для галереи на
  Android 13+ `image_picker` дополнительных настроек не требует.

## Как это работает
- Карта рисуется слоями: фон, фото, рамка класса, логотип, тексты. Размер 1338×828.
- Фото не обрезается физически: в библиотеке лежит оригинал, в проекте только масштаб
  и смещение. Перетаскивание и щипок прямо по карте, плюс ползунок.
- В рамке уже нарисовано «WD», приложение дорисовывает R, F или 4.
- Теги (можно несколько) рисуются над картой, метка призовой машины (кубок и текст) под картой, как в игре,
  на тёмной подложке. При экспорте они включены по умолчанию, переключателем можно
  сохранить только саму карту. Текст метки приза можно менять.
- Логотип рисуется в блоке размером с его место на карте (тёмная плитка слева сверху).
  Размер логотипа внутри блока меняется ползунком, в панели виден тот же блок в том же
  соотношении сторон.
- Удаление фото из библиотеки не ломает карточки: они остаются без фото.

## Удаление фона у логотипа
В разделе «Brand logo» после выбора логотипа появляется кнопка **Remove background**.
Алгоритм работает офлайн: от краёв картинки (или от точки, на которую нажмёшь) он
«заливает» пиксели похожего цвета и делает их прозрачными.
- **Tolerance**: насколько близкий цвет считается фоном (больше = удаляется больше).
- **Edge**: убирает светлую кайму по контуру и смягчает границу.
- **Only connected area**: включено, значит, удаляется только связный участок (белая
  внутренность логотипа останется); выключено, значит, цвет удаляется везде.
- **Auto / Undo / Clear**: автоматический фон по краям, отмена шага, сброс.
Результат сохраняется как **новый** логотип в библиотеке (оригинал не трогается),
лишние прозрачные поля обрезаются. На карте логотип теперь рисуется целиком,
без обрезки по кругу.
Лучше всего работает на логотипах с однотонным фоном. Вырезать машину из фотографии
таким способом нельзя: для этого нужна нейросеть (можно добавить позже).

## Конструктор тегов
Раздел «Tags and prize marker» → **Create tag**. Вводишь текст и выбираешь цвет бортика
(палитра или hex). Фон тега автоматически получается тем же цветом, но примерно в 4.55 раза
темнее (так устроены готовые теги), текст белый, ширина тега зависит от длины текста.
Нажатие на созданный тег открывает его редактирование. Можно смешивать готовые и свои теги,
порядок слева направо. Пропорции (толщина бортика, скругление, отступы, размер текста) взяты
из замеров готовых тегов, константы лежат в `lib/editor/canvas/custom_tag_view.dart`.

### Фото: перемещение, поворот, достройка краёв, размытие
- Фото можно двигать по всей карточке (в том числе так, что его край уходит внутрь карточки),
  уменьшать (до 0.4), увеличивать (до 6), поворачивать двумя пальцами или ползунком и кнопками на 90°.
  Теги над карточкой и метка приза под ней в этом не участвуют.
- **Content-aware** (заливка с учётом содержимого, как «Expand» в Snapseed или Content-Aware Fill
  в Photoshop): недостающее место собирается из кусочков самого фото (алгоритм PatchMatch), так что
  небо, деревья, трава и разметка дороги продолжаются. Работает офлайн, без нейросетей. Когда кадр
  выбран, нажми **Generate fill** (несколько секунд). Если потом сдвинуть, повернуть или увеличить
  фото, заливку нужно сгенерировать заново, а до этого показывается режим Mirror. Лучше всего работает
  на однородном фоне (небо, асфальт, трава, деревья); если машина обрезана краем фото, продолжение
  вокруг неё может получиться неточным. Это не генеративная нейросеть и не «дорисует» то, чего на
  фото нет (например, недостающую часть кузова).
- Остальные режимы заливки: **Mirror + blur** (края зеркалятся и размываются, небо, дорога и трава «продолжаются»),
  **Blurred backdrop** (размытая увеличенная копия фото позади) и **Flat colour**. Это достройка краёв,
  а не нейросетевая дорисовка: настоящую «генерацию продолжения» без интернета сделать нельзя.
- За полупрозрачными частями рамки (верхняя полоса и панели с характеристиками) фото размыто, как в игре.
  Области и сила размытия задаются в `assets/templates/standard.json`: `blurRegions` и `blurSigma`
  (0 отключает эффект).
- В окне ⓘ на главном экране есть ползунок «Fine-tune: tyre name height» для тонкой подгонки высоты
  названия шин относительно буквы T.

### Обрезанное фото
В окне экспорта (значок «поделиться» в редакторе) есть пункты **Save cropped photo** и
**Share cropped photo**. Сохраняется только фото в том кадре, который виден на карточке
(без рамки, текста и тегов), в пропорциях карточки, с поворотом и достроенными краями, и с разрешением
оригинала (но не шире 4096 пикселей), то есть чётче, чем фото на самой карточке.

### Размеры взяты с карточки-образца
Размеры названия, тегов, метки приза и фона под ними сверены с карточкой другого игрока
(сделанной в Photoshop) в одном масштабе. Фон под тегами и меткой приза теперь чёрный,
размытие за панелями слабее (`blurSigma` 8).

### Размеры и логотип
- Раздел **Sizes** меняет размер строки «марка + модель», года и тегов для конкретной карточки
  (ползунок от 0.6 до 1.6, 1.0 равно размеру из шаблона). Базовые размеры шаблона подобраны так: год
  чуть меньше, марка и модель и теги крупнее, чем раньше.
- У логотипа: перетаскивание внутри блока, ползунок размера, кнопка **Trim margins** (обрезает пустые
  поля вокруг логотипа, чтобы по центру блока стоял сам логотип, а не его картинка с полями) и
  **Remove background**.

### Свои теги, порядок, N/A
- Созданный тег сохраняется в «My tags» и появляется в выборе тегов (вкладки **All** и **My tags**).
  Во вкладке All готовые и свои теги идут общим списком по алфавиту. Во вкладке My tags свои теги
  можно создавать, править и удалять (меню «⋮»). Карточки, где тег уже использован, хранят свою копию.
- Теги на карточке можно перетаскивать за значок слева, чтобы поменять порядок.
- Если максимальная скорость меньше 60, вместо разгона 0-60 на карточке пишется **N/A**
  (тем же шрифтом и размером).
- Новые карточки создаются с пустыми полями года, RQ, скорости, разгона и управления.
  Brand и Model получают значения-заглушки.

## Рамки карточек
Сейчас используются рамки по редкости (`common`, `uncommon`, `rare`, `super_rare`, `epic`,
`legendary`, `ultra_rare`). Соответствие буквам классов S…F задаётся в `frames` внутри
`assets/templates/standard.json`. Старые рамки `S…F.png` остались в `assets/frames/` без
изменений на случай, если понадобятся. Слово «Tyres» теперь берётся из самой рамки,
приложение дорисовывает только название шин перед ним.

### Название шин и буква T
Название шин выравнивается не по центру строки, а по нижней линии буквы T из слова «Tyres»
(она часть рамки). В `assets/templates/standard.json`, поле `tyre`: `baseline` задаёт эту линию
(800.3), а `size` подобран так, чтобы высота заглавных букв совпала с высотой T. Если когда-нибудь
поменяешь рамки, замерь T заново и поправь эти два числа. Чем больше `baseline`, тем ниже текст.

## Размер текста
Текст на карте не зависит от настройки размера шрифта в телефоне (раньше зависел, из-за
чего размеры «плавали» от телефона к телефону). Все размеры шрифтов задаются в
`assets/templates/standard.json`, а параметр `textScale` (сейчас 0.9) умножает их все сразу:
если весь текст на картах кажется чуть крупным или мелким, меняй только его.

## Подгонка координат
Включи `AppConstants.debugGuides = true` (`lib/core/app_constants.dart`), чтобы увидеть
рамки полей на карте, и правь `x, y, w, h, size` в `assets/templates/standard.json`.
Текст центруется по вертикали внутри своего прямоугольника и сам уменьшается, если не влезает.
Для баннера приза значение `prizeVisibleWidth` обрезает пустую прозрачную часть картинки.

## Сборка APK и обновления

Подписанный APK собирает GitHub Actions (`.github/workflows/build-apk.yml`) и
кладёт его в раздел **Releases** репозитория. Папка `android/` в репозитории не
хранится: workflow создаёт её сам через `flutter create` и правит скриптом
`tool/patch_android.py` (добавляет разрешения и название приложения).

Чтобы Android ставил новую версию **поверх** старой с сохранением данных,
должны совпадать три вещи, и все три обеспечены:

1. **Одно и то же имя пакета.** Оно задаётся `APP_ORG` в workflow
   (`com.fancardmaker.topdrives_card_maker`). После первого выпуска не меняй.
2. **Одна и та же подпись.** Ключ хранится в секретах репозитория.
3. **Растущий versionCode.** Он считается из номера версии:
   `X.Y.Z` → `X*1000000 + Y*1000 + Z` (например 0.1.0 → 1000, 0.1.1 → 1001).

### Ключ подписи (делается один раз)

На компьютере с JDK (он есть в Android Studio) выполни:

```bash
keytool -genkey -v -keystore card-maker.jks -keyalg RSA -keysize 2048 \
  -validity 10000 -alias cardmaker
```

Придумай пароль (запомни его) и сохрани файл `card-maker.jks` в надёжном месте
вне репозитория. **Если потерять этот файл, обновить уже установленное приложение
будет нельзя**, придётся ставить заново.

Переведи файл в base64:

```bash
base64 -w0 card-maker.jks        # Linux / Git Bash
# PowerShell:
[Convert]::ToBase64String([IO.File]::ReadAllBytes("card-maker.jks"))
```

В репозитории на GitHub: Settings → Secrets and variables → Actions → New repository
secret. Создай четыре секрета:

| Имя | Значение |
|---|---|
| `KEYSTORE_BASE64` | результат base64 |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | `cardmaker` (алиас из команды выше) |
| `KEY_PASSWORD` | пароль ключа (если не задавал отдельный, тот же) |

### Выпуск новой версии

Сборка запускается сама при каждом `push` в ветку `main` (или `master`), если
изменились не только `.md`-файлы. Версия получается автоматически:
`major.minor` из `version:` в `pubspec.yaml` плюс номер запуска workflow, например
`0.1.7`. Чтобы выпустить «большую» версию, поменяй в `pubspec.yaml` например
`0.1.0+1` на `0.2.0+1`, следующая сборка будет `0.2.N`.

Можно и вручную: тег `git tag v1.0.0 && git push origin v1.0.0` или
Actions → Build APK → Run workflow с вводом версии.

Через несколько минут в Releases появится `card-maker-vX.Y.Z.apk`.
Версия в pubspec.yaml при сборке в CI подменяется вычисленной.

### Где скачать готовый APK
- **Releases** (постоянно): справа на главной странице репозитория, раздел Releases.
- **Artifacts** (30 дней): Actions → нужный запуск → внизу страницы раздел Artifacts.
  Скачивается zip-архив, внутри которого лежит APK; нужно войти в GitHub.
  Файл сохраняется, даже если публикация релиза не удалась.

### Если сборка не запускается
- Файл должен лежать в корне репозитория по пути `.github/workflows/build-apk.yml`
  (не внутри вложенной папки `topdrives_card_maker/`). Проект нужно класть в корень.
- Браузерная загрузка папок на GitHub иногда пропускает скрытую папку `.github`.
  Проверь, что она есть в репозитории; если нет, создай файл через
  Add file → Create new file, указав путь `.github/workflows/build-apk.yml`.
- Открой вкладку Actions: если там кнопка «I understand my workflows, go ahead and
  enable them», включи Actions.
- Пуш должен идти в `main` или `master` (проверь имя ветки по умолчанию).

### Установка и обновление на телефоне

1. Первый раз: скачай APK из Releases и установи (разреши установку из неизвестных источников).
2. Дальше приложение при запуске само проверяет последний релиз (если есть интернет)
   и предлагает скачать новую версию. Открой скачанный APK, Android предложит
   «Обновить», карточки и библиотека сохранятся.
3. Кнопка ⓘ на главном экране показывает версию и умеет проверять обновления вручную.

Ограничения:
- Репозиторий должен быть **публичным**: проверка читает релиз без авторизации.
  В приватном репозитории проверка не сработает (APK придётся скачивать вручную).
- Сборка, запущенная командой `flutter run`, подписана отладочным ключом. Поверх неё
  релизный APK не встанет: сначала удали такую версию (карточки при этом пропадут).
- Если когда-нибудь поменяешь `APP_ORG` или ключ, обновление поверх станет невозможным.

## Если приложение не открывается (чёрный экран, «не отвечает»)
При запуске приложение сразу показывает экран загрузки с текущим шагом
(«Opening app storage…», «Loading templates…» и т. д.). Если запуск упал с ошибкой
на уровне Dart, будет экран «Start-up failed» с текстом ошибки (его можно выделить
и скопировать). Если экран завис на каком-то шаге, запомни надпись.

Если приложение вылетает ещё до этого экрана, нужен системный лог телефона:
1. На телефоне включи «Отладка по USB» (Настройки → Для разработчиков), подключи по USB.
2. На компьютере (нужен adb из Android Studio / platform-tools):
   ```bash
   adb logcat -c
   # открой приложение, дождись вылета
   adb logcat -d > log.txt
   ```
3. Пришли строки из `log.txt` со словами `FATAL`, `AndroidRuntime`, `flutter`, `ANR`.
