# Card Maker (Top Drives fan cards)

Офлайн-приложение на Flutter для создания фанатских карточек. Все шаблоны,
рамки классов, теги и баннер приза уже внутри приложения (assets/).

> Код написан без запуска Flutter (в среде, где я его писал, Flutter не было),
> поэтому первый запуск, скорее всего, потребует мелких правок. Координаты текста
> в `assets/templates/standard.json` подобраны по твоим скриншотам и рамке B и
> нуждаются в подгонке на глаз.

## Первый запуск

```bash
cd topdrives_card_maker
flutter create --platforms=android,ios --project-name topdrives_card_maker .
# проверь, что lib/main.dart остался нашим (если нет, верни из архива)
flutter pub get
flutter run
```

### Шрифт
Roboto Condensed (лицензия SIL OFL) уже лежит в `assets/fonts/` и подключён в `pubspec.yaml`,
ничего докачивать не нужно.

### Разрешения
- **iOS** (`ios/Runner/Info.plist`): `NSPhotoLibraryUsageDescription`
  и `NSPhotoLibraryAddUsageDescription`.
- **Android**: `minSdkVersion 21` (нужно для пакета `gal`); для галереи на
  Android 13+ `image_picker` дополнительных настроек не требует.

## Как это работает
- Карта рисуется слоями: фон, фото, рамка класса, логотип, тексты. Размер 1338×828.
- Фото не обрезается физически: в библиотеке лежит оригинал, в проекте только масштаб
  и смещение. Перетаскивание и щипок прямо по карте, плюс ползунок.
- В рамке уже нарисовано «WD», приложение дорисовывает R, F или 4.
- Теги (можно несколько) рисуются над картой, метка призовой машины (кубок и текст) под картой, как в игре,
  на тёмной подложке. При экспорте они включены по умолчанию, переключателем можно
  сохранить только саму карту. Текст метки приза можно менять.
- Логотип рисуется в блоке размером с его место на карте (тёмная плитка слева сверху).
  Размер логотипа внутри блока меняется ползунком, в панели виден тот же блок в том же
  соотношении сторон.
- Удаление фото из библиотеки не ломает карточки: они остаются без фото.

## Удаление фона у логотипа
В разделе «Brand logo» после выбора логотипа появляется кнопка **Remove background**.
Алгоритм работает офлайн: от краёв картинки (или от точки, на которую нажмёшь) он
«заливает» пиксели похожего цвета и делает их прозрачными.
- **Tolerance**: насколько близкий цвет считается фоном (больше = удаляется больше).
- **Edge**: убирает светлую кайму по контуру и смягчает границу.
- **Only connected area**: включено, значит, удаляется только связный участок (белая
  внутренность логотипа останется); выключено, значит, цвет удаляется везде.
- **Auto / Undo / Clear**: автоматический фон по краям, отмена шага, сброс.
Результат сохраняется как **новый** логотип в библиотеке (оригинал не трогается),
лишние прозрачные поля обрезаются. На карте логотип теперь рисуется целиком,
без обрезки по кругу.
Лучше всего работает на логотипах с однотонным фоном. Вырезать машину из фотографии
таким способом нельзя: для этого нужна нейросеть (можно добавить позже).

## Конструктор тегов
Раздел «Tags and prize marker» → **Create tag**. Вводишь текст и выбираешь цвет бортика
(палитра или hex). Фон тега автоматически получается тем же цветом, но примерно в 4.55 раза
темнее (так устроены готовые теги), текст белый, ширина тега зависит от длины текста.
Нажатие на созданный тег открывает его редактирование. Можно смешивать готовые и свои теги,
порядок слева направо. Пропорции (толщина бортика, скругление, отступы, размер текста) взяты
из замеров готовых тегов, константы лежат в `lib/editor/canvas/custom_tag_view.dart`.

### Фото: перемещение, поворот, достройка краёв, размытие
- Фото можно двигать по всей карточке (в том числе так, что его край уходит внутрь карточки),
  уменьшать (до 0.4), увеличивать (до 6), поворачивать двумя пальцами или ползунком и кнопками на 90°.
  Теги над карточкой и метка приза под ней в этом не участвуют.
- **Content-aware** (заливка с учётом содержимого, как «Expand» в Snapseed или Content-Aware Fill
  в Photoshop): недостающее место собирается из кусочков самого фото (алгоритм PatchMatch), так что
  небо, деревья, трава и разметка дороги продолжаются. Работает офлайн, без нейросетей. Когда кадр
  выбран, нажми **Generate fill** (несколько секунд). Если потом сдвинуть, повернуть или увеличить
  фото, заливку нужно сгенерировать заново, а до этого показывается режим Mirror. Лучше всего работает
  на однородном фоне (небо, асфальт, трава, деревья); если машина обрезана краем фото, продолжение
  вокруг неё может получиться неточным. Это не генеративная нейросеть и не «дорисует» то, чего на
  фото нет (например, недостающую часть кузова).
- Остальные режимы заливки: **Mirror + blur** (края зеркалятся и размываются, небо, дорога и трава «продолжаются»),
  **Blurred backdrop** (размытая увеличенная копия фото позади) и **Flat colour**. Это достройка краёв,
  а не нейросетевая дорисовка: настоящую «генерацию продолжения» без интернета сделать нельзя.
- За полупрозрачными частями рамки (верхняя полоса и панели с характеристиками) фото размыто, как в игре.
  Области и сила размытия задаются в `assets/templates/standard.json`: `blurRegions` и `blurSigma`
  (0 отключает эффект).
- В окне ⓘ на главном экране есть ползунок «Fine-tune: tyre name height» для тонкой подгонки высоты
  названия шин относительно буквы T.

### Пустые значения у новой карточки
У новой карточки **шаблон, привод, шины и страна не выбраны** (класс по-прежнему B). Выбираешь нужное в блоках
Style, Drive, Tyres и Country, повторное нажатие на выбранное значение снимает выбор. Пока шаблон не выбран,
карточка рисуется стандартным шаблоном. Пока привод и шины пусты, на карточке остаются только слова рамки («WD» и
«Tyres»), пока пуста страна, поле страны пустое. Старые карточки сохраняют свои значения.

### Шаблон Beta (карточки из бета-теста игры)
Третий шаблон в блоке **Style → Template**. Это вид карточек из бета-теста: сверху плитка логотипа, название, год и
код страны, справа четыре плитки (**TOP SPEED**, **0-60MPH**, **WEIGHT** и две маленькие **WD** и **GRIP**), слева
снизу цветная плашка с числом (поле **RQ**) и значком ключа. Плашка и есть класс: в этом шаблоне пять классов,
в блоке **Class** пять чипов с цветной точкой: S жёлтый, A фиолетовый, B голубой, C зелёный, D серый. Пока класс не
выбран, плашка тёмная (без цвета класса). Что отличается от остальных шаблонов:
- появилось поле **Weight** (вес), оно показывается в «Car data» только для этого шаблона;
- поле **Handling** в нём называется **Grip**;
- блока **Tyres** нет, потому что в этой карточке шин нет, а блок **Tyres** в редакторе скрывается;
- полосок прокачки над блоком RQ нет (в игре они показывают, насколько прокачана машина, нам они не нужны);
- рамка рисуется без размытия фона, а сохранение «High» даёт ровно 2400 пикселей в ширину.
Рамки (`assets/frames/beta/S…D.png` и `none.png`, 2400x1494) перерисованы в полном размере скриптом
`python3 tool/make_beta_frames.py путь/к/маленькой_рамке.png` из пяти маленьких картинок 597x372: плитки, подписи
(шрифтом Roboto Condensed) и плашка рисуются заново, чтобы подписи не были мутными. Из маленькой рамки берётся только
значок ключа. Параметры шаблона (позиции текста, размеры, цвета классов) лежат в `assets/templates/beta.json`.

### Новая карточка пустая
У новой карточки ничего не выбрано: **шаблон**, **класс**, **страна**, **привод** и **шины** пустые (ни один чип не
подсвечен), **Brand** и **Model** пустые, а слова «Brand» и «Model» видны внутри полей только как подсказка (исчезают, как
только начнёшь писать). Пока шаблон не выбран, карточка рисуется стандартным шаблоном, пока не выбран класс, рамкой
без плашки класса: слева снизу нет цветной плашки с буквой, остаётся серая панель с рейтингом, а метка RQ
и звёзды нейтральные (серые). Выбранный чип шаблона или класса снимается повторным нажатием. Старые карточки не меняются.

### Рамка без класса
Рамки `assets/frames/none.png` (стандартный шаблон) и `assets/frames/modern/none.png` (Modern) получены из рамки класса B
скриптом `python3 tool/make_noclass_frames.py` (запускать из корня проекта): из неё убрана плашка класса слева снизу, а
цветные RQ и звёзды сделаны нейтральными. В шаблонах рамка записана под ключом `none`. Если рамки классов когда-нибудь
перерисуешь (в том числе `tool/make_modern_frames.py`), прогони этот скрипт ещё раз.

### Теги по фото и сохранение тегов на телефон
В окне выбора тегов, на вкладке **My tags**, рядом с **Create tag** есть кнопка **Tag from photo**: выбираешь картинку
в галерее (например, скриншот тега), пишешь название и при желании включаешь **Remove background** (откроется тот же
редактор фона, что для логотипов). Если фон не убирать, пустые поля вокруг тега по возможности обрезаются. Тег появляется
в **My tags** и в общем списке, рисуется над карточкой как готовые теги (размер задаёт общий ползунок размера тегов).
У тега из фото в меню (три точки) есть **Rename**, **Save to phone** и **Delete**; у тега из текста **Edit** вместо Rename.
**Save to phone** (и долгое нажатие на любой тег, в том числе готовый) кладёт тег PNG-картинкой в галерею.
Текст своих тегов (из текста и цвета) набран шрифтом Roboto Medium обычной ширины, как у игровых тегов: размер
0.505 высоты тега без добавочного расстояния между буквами, подобрано по готовым тегам (ширина слов совпадает до
пикселя). Шрифт лежит в `assets/fonts/Roboto-Medium.ttf`, объявлен в `pubspec.yaml` как `TagRoboto`.
Сохранение тега на телефон рисует его сразу в картинку (около 600 пикселей в высоту), без показа на экране; результат
(«Tag saved to the gallery» или причина ошибки) появляется строкой под вкладками.
Картинки тегов лежат в папке приложения `tag_images`; при удалении тега из **My tags** файл не стирается, чтобы карточки,
которые его уже используют, ничего не потеряли.

### Свой привод и свои шины
В блоках **Drive** и **Tyres** рядом с готовыми значениями есть кнопка **Custom**: вводишь своё значение, оно сразу
выбирается и остаётся в списке для других карточек (долгое нажатие на своём значении удаляет его из списка, карточки,
где оно уже стоит, не меняются). Для привода на карточке рисуется только первая буква, потому что «WD» уже есть в
рамке (AWD даст «A» + «WD»). Название шин рисуется заглавными перед словом «Tyres» из рамки, до 14 символов.
Списки хранятся в `settings.json` (`customDrives`, `customTyres`).

### Скорость в км/ч
Под полем **Top speed** есть кнопка **km/h → mph**. Введи скорость в км/ч и нажми её: число в поле само заменится
на мили (округлённые, 1 км/ч = 0.621371 mph) и сразу попадёт на карточку. Сразу после перевода та же кнопка
превращается в **Undo (число)** и возвращает исходные км/ч, так что случайное второе нажатие не переведёт число дважды.
Если начать править поле руками, кнопка снова становится «km/h → mph». Пока в поле нет числа, кнопка неактивна.

### Битые кадры и мусор в углу картинки
Иногда GPU телефона случайно портит снимок карточки: блок мусора в левом верхнем углу или весь кадр. Поэтому и
картинки, и каждый кадр видео (MP4 и GIF) снимаются несколько раз, пока два снимка не совпадут побайтово: испорченный
снимок каждый раз получается разный и совпасть с другим не может. Цена: экспорт видео идёт минимум вдвое дольше.
Если за 14 попыток для кадра так и не нашлось двух одинаковых снимков, экспорт останавливается с ошибкой
(лучше без файла, чем с битым).

### Обрезанное фото
В окне экспорта (значок «поделиться» в редакторе) есть пункты **Save cropped photo** и
**Share cropped photo**. Сохраняется только фото в том кадре, который виден на карточке
(без рамки, текста и тегов), в пропорциях карточки, с поворотом и достроенными краями, и с разрешением
оригинала (но не шире 4096 пикселей), то есть чётче, чем фото на самой карточке.

### Размеры взяты с карточки-образца
Размеры названия, тегов, метки приза и фона под ними сверены с карточкой другого игрока
(сделанной в Photoshop) в одном масштабе. Фон под тегами и меткой приза теперь чёрный,
размытие за панелями слабее (`blurSigma` 8).

### Размеры и логотип
- Раздел **Sizes** меняет размер марки, модели, года и тегов для конкретной карточки
  (ползунок от 0.6 до 1.6, 1.0 равно размеру из шаблона). **Brand** задаёт точный размер марки: он не
  зависит от длины текста. **Model (max)** задаёт наибольший размер модели: длинное название
  автоматически уменьшается, чтобы поместиться в строку (см. «Стили карточки»).
- У логотипа: перетаскивание внутри блока, ползунок размера, кнопка **Trim margins** (обрезает пустые
  поля вокруг логотипа, чтобы по центру блока стоял сам логотип, а не его картинка с полями) и
  **Remove background**.

### Свои теги, порядок, N/A
- Созданный тег сохраняется в «My tags» и появляется в выборе тегов (вкладки **All** и **My tags**).
  Во вкладке All готовые и свои теги идут общим списком по алфавиту. Во вкладке My tags свои теги
  можно создавать, править и удалять (меню «⋮»). Карточки, где тег уже использован, хранят свою копию.
- Теги на карточке можно перетаскивать за значок слева, чтобы поменять порядок.
- Если максимальная скорость меньше 60, вместо разгона 0-60 на карточке пишется **N/A**
  (тем же шрифтом и размером).
- Новые карточки создаются с пустыми полями года, RQ, скорости, разгона и управления.
  Brand и Model получают значения-заглушки.

## Альбомы
Кнопка **Albums** на главном экране открывает страницу с двумя вкладками.
- **By brand**: встроенные альбомы. Они создаются сами по полю **Brand** карточек (регистр и пробелы по краям не важны:
  «Porsche» и « porsche » это один альбом). Бренды идут по алфавиту, карточки без бренда собраны в «No brand» в конце,
  внутри альбома карточки отсортированы по модели. Альбом бренда не хранится, он пересчитывается при каждом открытии,
  поэтому сменил бренд у карточки, и она сама переехала в другой альбом. Значок альбома: логотип первой карточки бренда с логотипом.
- **My albums**: свои альбомы. Создаются кнопкой «+» (в списке или в шапке), в альбом добавляется любая карточка кнопкой
  **Add cars** (выбираешь галочками, сохраняется по **Done**). Альбом можно переименовать и удалить (карточки при этом остаются).
- Одна карточка может лежать в нескольких своих альбомах. Долгое нажатие на карточку (на главном экране или в альбоме): **Add to album**
  (галочки по альбомам и **New album**), а внутри своего альбома ещё **Remove from album**.
- Удаление карточки убирает её из всех альбомов. Дубликат карточки в альбомы не попадает.
- **Поиск.** На главном экране (все карточки) строка поиска ищет по бренду, модели и названию карточки; слова через пробел
  должны встретиться все, регистр не важен. На вкладке **By brand** она ищет только по названию бренда; на вкладке **My albums** ищет по названию альбома. Код: `lib/data/card_search.dart`,
  `lib/ui/common/search_field.dart`.
- Хранение: `card_maker/albums.json` (список альбомов с id карточек). Код: `lib/ui/albums/`, `lib/data/models/album.dart`,
  `lib/data/repositories/album_repository.dart`, `lib/data/brand_groups.dart`.

## Рамки карточек
Сейчас используются рамки по редкости (`common`, `uncommon`, `rare`, `super_rare`, `epic`,
`legendary`, `ultra_rare`). Соответствие буквам классов S…F задаётся в `frames` внутри
`assets/templates/standard.json`. Старые рамки `S…F.png` остались в `assets/frames/` без
изменений на случай, если понадобятся. Слово «Tyres» теперь берётся из самой рамки,
приложение дорисовывает только название шин перед ним.

### Название шин и буква T
Название шин выравнивается не по центру строки, а по нижней линии буквы T из слова «Tyres»
(она часть рамки). В `assets/templates/standard.json`, поле `tyre`: `baseline` задаёт эту линию
(800.3), а `size` подобран так, чтобы высота заглавных букв совпала с высотой T. Если когда-нибудь
поменяешь рамки, замерь T заново и поправь эти два числа. Чем больше `baseline`, тем ниже текст.

## Шаблоны и флаг страны
- **Шаблоны.** Шаблон это JSON в `assets/templates/` (положение полей, размытие, пути к рамкам) плюс семь
  PNG-рамок по классам. Список лежит в `TemplateRegistry`. Сейчас два: **Standard** и **Modern**.
  Переключатель шаблона находится в разделе **Style**, шаблон хранится в карточке (`templateId`).
- **Modern** это вид новых карточек игры: нет звёздочек, ключ тюнинга ниже и крупнее, нет тёмной полосы
  внизу (больше места для фото), панели характеристик, которые нарастают от полностью прозрачных слева до тёмных справа
  (размытие фона под ними тоже нарастает плавно: ключ `fadeLeft` у областей `blurRegions`), блок RQ без
  буквы класса: плоский цвет класса, над ним прозрачный «клетчатый флаг» из квадратов цвета класса,
  затухающий вверх, число RQ тёмное. Строка заголовка нейтрально-серая (как на новых карточках; у Standard
  она тёплая коричневая), текст названия мельче (бренд ≈54.5, `titleStyles.fan` в `modern.json`), а подпись шин
  сдвинута на 15 единиц влево, как в игре.
  Рамки собираются из стандартных скриптом `python3 tool/make_modern_frames.py` (название, блок логотипа,
  блок страны и подписи под цифрами берутся из стандартной рамки без изменений). Числа (положение плиток,
  градиент, положение ключа и логотипа RQ) измерены по скриншоту карточки Porsche 911 GT2 и лежат в
  начале скрипта. Образец был только класса A; цвета остальных классов взяты из стандартных рамок.
- **Флаг за кодом страны** это опция карточки (переключатель в блоке **Country**), она работает в любом
  шаблоне. Флаг рисуется кодом (`lib/data/country_flags.dart`, упрощённо, без гербов) и заполняет блок
  страны со скошенным левым краем. Форма и прозрачность (на эталоне Modern измерено 0.50, у Standard 0.62, чтобы белые буквы кода читались на светлых флагах): раздел `flag` в JSON шаблона (`points`, `opacity`).
  Флаги есть для всех встроенных кодов (DE, IT, JP, US, GB, FR, SE, ES, NL, CZ, AT, CH, KR, CN, RU, UA, AU,
  CA, BR, IN). Для своего кода страны флага нет, переключатель ничего не покажет.
- Цвет текста поля задаётся в шаблоне ключом `color` (`"#RRGGBB"`), по умолчанию белый.

## Видео вместо фото (этап 1)
В блоке **Car photo or video** кнопка **Video** выбирает видео из галереи. Оно заменяет фото-слой и
двигается теми же жестами (сдвиг, зум, поворот), с тем же `PhotoTransform`. В предпросмотре играет
выбранный фрагмент (до 10 с, по умолчанию 6 с, ползунки **Start** и **Length**) по кругу без звука.
Всё остальное (рамка, текст, теги, приз) неподвижно поверх.

- Видео копируется в `card_maker/videos/`, рядом лежит кадр-постер `<файл>.poster-<мс>.jpg`. Постер
  работает как «фото»: он в сетке, в PNG-экспорте и под видео заполняет пустые края (mirror/blur).
- `smart`-заливка для видео недоступна (движущаяся картинка), для видео остаются mirror, blur, none.
- Кадры достаёт небольшой Kotlin-модуль (`MediaMetadataRetriever`, канал `card_maker/video`): его
  подкладывает `tool/patch_android.py` в `MainActivity.kt`. Сторонних плагинов для кадров нет.
- **Экспорт MP4** (этап 2): в листе экспорта у видео-карточки появляются «Save video (MP4) to gallery» и
  «Share video (MP4)», частота 24 или 30 кадров/с, полный размер карточки (1338×828, с тегами и призом,
  если включён переключатель). Каждый кадр видео подставляется в живую карточку (те же виджеты, что в
  предпросмотре: кадрирование, матовое стекло, рамка, текст), снимается как картинка и отдаётся кодировщику
  (`MediaCodec`, H.264, ~0.35 бит на пиксель, цвет BT.709). 6 секунд при 30 кадрах/с рендерятся порядка
  минуты, есть прогресс и отмена. Звука нет.
- **Экспорт GIF** (этап 3): «Save GIF to gallery» и «Share GIF». Частота 10, 20 или 25 кадров/с (в GIF
  задержка задаётся в сотых долях секунды, поэтому ровно получаются только эти частоты), размер Full,
  75% или 50%. Кадры рендерятся так же, как для MP4 (70% полосы прогресса) и сохраняются во временные
  сжатые файлы; затем фоновый изолят (`lib/video/gif_encoder.dart`) строит **одну общую палитру** из 256
  цветов по выборке кадров (median cut по 15-битной гистограмме, чтобы цвета не мерцали между кадрами),
  применяет дизеринг Флойда-Стейнберга (градиенты и матовое стекло без полос) и пишет файл по кадрам
  (LZW). Алгоритм проверен на Python: GIF декодируется Pillow без расхождений, PSNR ≈ 33 дБ.
  Вес в полном размере порядка 0.7-1 МБ на кадр (6 с при 20 кадрах/с это около 100 МБ), под выбором
  размера показана оценка. Для мессенджеров лучше MP4: он в десятки раз легче.
- PNG-экспорт видео-карточки сохраняет кадр-постер.

## Стили карточки
В разделе **Style** (над классом) выбирается вид карточки: **Fan-made** или **Game (official)**.
Стиль меняет только размеры текста названия и положение метки приза, а не содержимое. Выбор хранится
в карточке (`cardStyle`), у старых карточек по умолчанию Fan-made. Остальные поля (скорость, разгон,
год, страна и т. д.) в обоих стилях одинаковые: по замерам они совпадают.

| | Fan-made | Game (official) |
|---|---|---|
| Марка (жирная) | ~64.5 | ~44 |
| Модель | ~64.5 | ~46 |
| Базовая линия названия | 68 | 62 |
| Левый край названия | 158 | 154 |
| Метка приза | значок у левого края, текст в одну строку | значок отступает на ~70 и крупнее (~74), текст в две строки |

### Марка и модель
Марка и модель рисуются отдельно (`lib/editor/canvas/title_text.dart`) на общей базовой линии. Марка
всегда имеет свой размер, модель получает остаток строки. **Перенос работает одинаково в обоих стилях:**
если модель не помещается, она сначала уменьшается на одной строке до `twoLineScale` от своего размера,
а если пришлось бы мельче, переносится на две строки (марка встаёт посередине между ними).
В игровом стиле `twoLineScale` почти 1, поэтому там длинное название переносится сразу, как в игре.
В фан-стиле перенос рассчитан по тем же правилам, но размер на двух строках (0.7 от размера, то есть
~45) подобран расчётом, образца фан-карточки с двумя строками нет.

Числа лежат в `assets/templates/standard.json`, раздел `titleStyles` (размеры там до умножения на
`textScale`): `x`, `w` (до какого места можно писать), `brandSize`, `modelSize`, `baseline`, `gapEm`
(зазор между маркой и моделью в размерах марки), `wrap`, `twoLineScale`, `lineHeight` (расстояние между
двумя строками модели в размерах модели).

### Метка приза
Фан-стиль берёт значения из `extras.prize*` (как было). Игровой стиль задаётся разделом `prizeStyles.game`:
`paddingLeft`, `paddingTop`, `paddingBottom`, `iconHeight`, `iconCrop`, `iconDy` (сдвиг значка вниз, чтобы
его центр совпал с центром текста), `gap`, `textSize`, `textWidth` (ширина, на которой текст переносится),
`letterSpacing`, `textStroke`, `lineHeight`. Недостающие ключи берутся из значений по умолчанию.

## Размер текста
Текст на карте не зависит от настройки размера шрифта в телефоне (раньше зависел, из-за
чего размеры «плавали» от телефона к телефону). Все размеры шрифтов задаются в
`assets/templates/standard.json`, а параметр `textScale` (сейчас 0.9) умножает их все сразу:
если весь текст на картах кажется чуть крупным или мелким, меняй только его.

## Подгонка координат
Включи `AppConstants.debugGuides = true` (`lib/core/app_constants.dart`), чтобы увидеть
рамки полей на карте, и правь `x, y, w, h, size` в `assets/templates/standard.json`.
Текст центруется по вертикали внутри своего прямоугольника и сам уменьшается, если не влезает.
Для баннера приза значение `prizeVisibleWidth` обрезает пустую прозрачную часть картинки.

## Сборка APK и обновления

Подписанный APK собирает GitHub Actions (`.github/workflows/build-apk.yml`) и
кладёт его в раздел **Releases** репозитория. Папка `android/` в репозитории не
хранится: workflow создаёт её сам через `flutter create` и правит скриптом
`tool/patch_android.py` (добавляет разрешения и название приложения).

Чтобы Android ставил новую версию **поверх** старой с сохранением данных,
должны совпадать три вещи, и все три обеспечены:

1. **Одно и то же имя пакета.** Оно задаётся `APP_ORG` в workflow
   (`com.fancardmaker.topdrives_card_maker`). После первого выпуска не меняй.
2. **Одна и та же подпись.** Ключ хранится в секретах репозитория.
3. **Растущий versionCode.** Он считается из номера версии:
   `X.Y.Z` → `X*1000000 + Y*1000 + Z` (например 0.1.0 → 1000, 0.1.1 → 1001).

### Ключ подписи (делается один раз)

На компьютере с JDK (он есть в Android Studio) выполни:

```bash
keytool -genkey -v -keystore card-maker.jks -keyalg RSA -keysize 2048 \
  -validity 10000 -alias cardmaker
```

Придумай пароль (запомни его) и сохрани файл `card-maker.jks` в надёжном месте
вне репозитория. **Если потерять этот файл, обновить уже установленное приложение
будет нельзя**, придётся ставить заново.

Переведи файл в base64:

```bash
base64 -w0 card-maker.jks        # Linux / Git Bash
# PowerShell:
[Convert]::ToBase64String([IO.File]::ReadAllBytes("card-maker.jks"))
```

В репозитории на GitHub: Settings → Secrets and variables → Actions → New repository
secret. Создай четыре секрета:

| Имя | Значение |
|---|---|
| `KEYSTORE_BASE64` | результат base64 |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | `cardmaker` (алиас из команды выше) |
| `KEY_PASSWORD` | пароль ключа (если не задавал отдельный, тот же) |

### Выпуск новой версии

Сборка запускается сама при каждом `push` в ветку `main` (или `master`), если
изменились не только `.md`-файлы. Версия получается автоматически:
`major.minor` из `version:` в `pubspec.yaml` плюс номер запуска workflow, например
`0.1.7`. Чтобы выпустить «большую» версию, поменяй в `pubspec.yaml` например
`0.1.0+1` на `0.2.0+1`, следующая сборка будет `0.2.N`.

Можно и вручную: тег `git tag v1.0.0 && git push origin v1.0.0` или
Actions → Build APK → Run workflow с вводом версии.

Через несколько минут в Releases появится `card-maker-vX.Y.Z.apk`.
Версия в pubspec.yaml при сборке в CI подменяется вычисленной.

### Где скачать готовый APK
- **Releases** (постоянно): справа на главной странице репозитория, раздел Releases.
- **Artifacts** (30 дней): Actions → нужный запуск → внизу страницы раздел Artifacts.
  Скачивается zip-архив, внутри которого лежит APK; нужно войти в GitHub.
  Файл сохраняется, даже если публикация релиза не удалась.

### Если сборка не запускается
- Файл должен лежать в корне репозитория по пути `.github/workflows/build-apk.yml`
  (не внутри вложенной папки `topdrives_card_maker/`). Проект нужно класть в корень.
- Браузерная загрузка папок на GitHub иногда пропускает скрытую папку `.github`.
  Проверь, что она есть в репозитории; если нет, создай файл через
  Add file → Create new file, указав путь `.github/workflows/build-apk.yml`.
- Открой вкладку Actions: если там кнопка «I understand my workflows, go ahead and
  enable them», включи Actions.
- Пуш должен идти в `main` или `master` (проверь имя ветки по умолчанию).

### Установка и обновление на телефоне

1. Первый раз: скачай APK из Releases и установи (разреши установку из неизвестных источников).
2. Дальше приложение при запуске само проверяет последний релиз (если есть интернет)
   и предлагает скачать новую версию. Открой скачанный APK, Android предложит
   «Обновить», карточки и библиотека сохранятся.
3. Кнопка ⓘ на главном экране показывает версию и умеет проверять обновления вручную.

Ограничения:
- Репозиторий должен быть **публичным**: проверка читает релиз без авторизации.
  В приватном репозитории проверка не сработает (APK придётся скачивать вручную).
- Сборка, запущенная командой `flutter run`, подписана отладочным ключом. Поверх неё
  релизный APK не встанет: сначала удали такую версию (карточки при этом пропадут).
- Если когда-нибудь поменяешь `APP_ORG` или ключ, обновление поверх станет невозможным.

## Если приложение не открывается (чёрный экран, «не отвечает»)
При запуске приложение сразу показывает экран загрузки с текущим шагом
(«Opening app storage…», «Loading templates…» и т. д.). Если запуск упал с ошибкой
на уровне Dart, будет экран «Start-up failed» с текстом ошибки (его можно выделить
и скопировать). Если экран завис на каком-то шаге, запомни надпись.

Если приложение вылетает ещё до этого экрана, нужен системный лог телефона:
1. На телефоне включи «Отладка по USB» (Настройки → Для разработчиков), подключи по USB.
2. На компьютере (нужен adb из Android Studio / platform-tools):
   ```bash
   adb logcat -c
   # открой приложение, дождись вылета
   adb logcat -d > log.txt
   ```
3. Пришли строки из `log.txt` со словами `FATAL`, `AndroidRuntime`, `flutter`, `ANR`.
